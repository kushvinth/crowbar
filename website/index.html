How it works

Vulnerability intelligence means knowing which vulnerabilities apply to what you actually run. Crowbar retrieves that data and indexes it locally, so your codebase can query it instead of guessing.

  1. Point at your stack

    Give crowbar a product, a version and a question.

  2. Crowbar retrieves and indexes

    It pulls real CPE ranges, KEV and EPSS scores, advisories and proof-of-concept metadata into a local database.

  3. Query it from your codebase

    You ask for the CVEs that apply, and crowbar answers from the index it just built.

Example 01 · CVE triage

Is Log4Shell worth patching?

You ask crowbar about CVE-2021-44228. It returns the record, the risk signals and the proof-of-concept code that already exists, so the answer is a decision and not a recap of a blog post.

1. Ask about the CVE

Example prompt · Log4Shell

›Use crowbar to triage CVE-2021-44228. Is it being exploited in the wild, how likely is it, and is there public proof-of-concept code?

2. Read the signals

Crowbar ranks the signals before the score. A CVSS number alone is not a risk verdict.

Is it exploited?
CISA KEV and SSVC exploitation state. KEV · ssvc=active
How likely?
EPSS, the 30-day exploitation probability. epss 1.00
What is the impact?
CVSS, only once the other signals are known. CRIT 10.0

3. Get the decision

crowbar answers with the fix, the evidence and the exploit code, then tells you what it cannot know.

Example 02 · Version matching

Which nginx CVEs affect 1.18.0?

Searching a product name returns everything that mentions nginx. Crowbar tests the version against the real CPE ranges, so the answer is the small list you actually have to act on.

1. Ask about the version

Example prompt · nginx

›We run nginx 1.18.0 in production. Use crowbar to find the CVEs that actually affect that version, and tell me what to upgrade to.

2. Only true hits

Every returned row carries the range that matched, so the agent can show its work instead of asserting a fact.

NVD CPE data is incomplete for some vendors. Cross-check with crowbar os for Windows, iOS and macOS.

3. Compare the two answers

Same product, two very different lists. One is a keyword hit, the other is an applicability answer.

By product name 
$ crowbar search --product nginx

  matched f5:nginx >=0.6.18 <1.20.1

Index tiers. Every tier ships the same commands; larger tiers only add sources.
Tier Size Includes
lite ~150 MB KEV, EPSS, recent CVEs, CWE
medium ~500 MB Full NVD, CAPEC, SSVC, ATT&CK
heavy ~2 GB Exploit-DB, Nuclei, Metasploit, OSV
extreme Full corpus MSRC, Apple, Debian, every source

Reference data, not a weapon.

Crowbar looks things up. It is not a scanner, and it is not permission to test anyone's systems.

  1. Authorization first.

    Only test hosts you own or are permitted to test. Crowbar answers questions; it does not touch anything.

  2. Exploits are untrusted code.

    crowbar exploit <id> downloads source for inspection. It never runs it. Use a disposable VM.

  3. KEV and SSVC describe elsewhere.

    They mean exploitation was observed in the wild, not that your host is affected.

  4. Absence is not safety.

    EPSS is a model estimate, and a missing row is not proof of “not affected”.
